# Требования к SpeechSense

## Функциональные
- Принимать русскоязычные голосовые отзывы Telegram; дополнительно текстовые отзывы.
- Бот передаёт аудио по сети на отдельный сервер.
- Сервер преобразует аудио в текст посредством Whisper и классифицирует текст выбранной по результатам исследования моделью.
- Возвращать целочисленную метку (0 neutral, 1 positive, 2 negative) и понятное пояснение; транскрипцию для аудио.
- Выявлять нерелевантные сообщения отдельным OOD-компонентом; не подменять нейтральный класс. Для OOD и ошибок отдельный статус, без принудительной метки тональности.
- Обрабатывать пустое аудио, неподдерживаемый формат, ошибки ASR и недоступность сервера.

## Требования к ML
- Описать покрытие, состав, качество данных и нормализацию; для аудио длительность, шум и качество транскрипций, если имеются измерения.
- Реализовать предобработку и обучить классические ML-модели, CNN/RNN на PyTorch и трансформеры с fine-tuning. Сохранить все исходные эксперименты и варианты улучшений.
- Рассчитать на test macro-F1, accuracy, weighted-F1, PR-AUC, confusion matrix; ROC-AUC для бинарных экспериментов, OvR дополнительно для трёх классов.
- Анализировать ошибки по классам, длине, источнику, предобработке и балансировке. Ансамбли подбирать на validation.
- Оценивать ASR отдельно (WER/CER при наличии эталонов), а также влияние ASR на результат классификации.

## Инженерные требования
- Воспроизводимые конфигурации, версии данных, seed, результаты и артефакты.
- Не хранить токены и пользовательские аудио в публичном репозитории. Удалять временные файлы; ограничивать размер входа, проверять форматы.
- Автоматические тесты маппинга, API, ASR, OOD и сквозной цепочки.
- Документировать запуск и демонстрацию. Жёсткого требования ко времени ответа нет.

Требования к продукту и исследованию, без привязки к номерам домашних заданий. OOD, текстовый ввод и инженерные меры — согласованные расширения проекта, а не исходные обязательные критерии преподавателя.
